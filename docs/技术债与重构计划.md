## 二、已知技术债（3 项，按严重度排序）

### 债 1 · 渲染流程骨架重复 4 份（最重）

- **证据**：4 个渲染 Operator 的 `execute` 归一化后 14 条公共语句；114 行里约 56 行重复。
  两两相似度：`still` vs `engine_anim` **0.74**、`preview` vs `still` **0.67**。
  业内重复率标准 <5%。
- **为什么现在不动**（关键，实测得出）：这 4 个里 **3 个结构性不可测** ——

  | Operator | 无头 `poll()` | 无头执行 | 可否自动化 |
  |---|---|---|---|
  | `wqr.preview` | True | ✗ OpenGL 限制 | **否** |
  | `wqr.render_still` | True | ✗ OpenGL 限制 | **否** |
  | `wqr.render_anim` | True | ✗ OpenGL 限制 | **否** |
  | `wqr.render_engine` | True | ✓ `{'FINISHED'}`（真的出了 mp4） | **是** |

  ⇒ 重构主要风险区（3 个 `render.opengl` 流程）**没有任何自动化护栏**，
  唯一验证手段是手工在 GUI 点按钮。**这是不该现在动手的最硬理由。**
- **触发条件**：新增第 5 种渲染方式（多机位 / 只出描边 / 批量队列等）

### 债 2 · `_PREVIEW` 状态重置手写 3 遍

- **证据**：四个字段各出现 3 处（行 717-720 / 945-948 / 968-971）。
- **风险**：结构一变就要同步改 3 处，漏一处不会报错 —— 上次新增 `"display"` 字段正好碰过这里。
- **成本**：只省约 8 行。
- **触发条件**：再往 `_PREVIEW` 加字段时（顺手抽 `_reset_preview_state()`）

### 债 3 · `WQR_PT_panel.draw()` 116 行 / 圈复杂度 15

- **证据**：全文件 45 项里唯一进 radon C 级；对照 Pylint 默认 `max-complexity=10` 会告警。
- **官方依据**：Blender 官方 Best Practice 原文 ——
  *"If you need more code for the layout declaration than for the actual properties, then you are doing it wrong."*
  官方自己的 `io_scene_fbx` / `io_scene_gltf2` 都把 `draw()` 拆成多个 `export_*` 辅助函数。
- **为什么现在不动**：只影响「加/删面板控件」时的可读性，每次碰的成本是「找位置 + 加两行」，可接受。
- **触发条件**：面板控件涨到约 30 个，或需要按条件折叠分组时

## 三、如果要改：执行顺序（按风险从低到高）

> 原则：**先补护栏，再动代码。** 每一步独立可交付、可回滚，改完立即跑三套回归。

### 第 0 步 · 补 `render_engine` 的回归测试（零风险，随时可做）

实测已证明它能无头跑通并真的产出 mp4。补一条测试覆盖「引擎式渲染 → 引擎还原 → 输出还原」，
把目前唯一可自动化的渲染链路纳入护栏。

- 注意：真渲染 1 帧（约数百 ms），输出指到临时目录，别污染用户工程
- 顺带覆盖：**失败路径下的 `finally` 还原**（本次探测意外验证了 3 个 opengl Operator
  在报错时仍正确还原了分辨率百分比、帧范围与输出路径 —— 这条路径此前从未被测过）

### 第 1 步 · 抽 `_reset_preview_state()`（低风险）

替换 3 处手写重置。预览开关全链路有 90 项测试覆盖，改完跑 `test_preview.py` 即可确认。

### 第 2 步 · `draw()` 拆分 + 用 stub layout 补测（中低风险）

拆成 `_draw_render_box(layout, scene)` / `_draw_preview_box(...)` / `_draw_shading_box(...)`，
`draw()` 只做分发。

- **可测性关键**：拆出的函数只调 `layout` 的方法（`box` / `row` / `label` / `prop` / `operator`），
  可以用 `unittest.mock.MagicMock` 当假 layout 传入 → **在无头下断言「调用了哪些控件、顺序如何」**
- 顺带修一个隐患：抽屉里按 `cavity_type` / `light` / `show_shadows` 条件显示控件，
  面板高度会跳；Blender 的惯例是保持布局稳定、把不适用项 `enabled = False` 灰掉

### 第 3 步 · 消掉 4 份重复骨架（高风险，须先做完第 0 步）

**不要把整个流程抽成一个 `_run_render()`** —— 那样会把唯一不可测的那行也包进去，
等于把不可测面积扩大。更好的切法是把「编排」与「渲染调用」分离：

```python
snap = _snapshot(scene)
_before_render(scene, video)              # 可无头测：precheck / 缩放 / 帧范围 / 输出准备
try:
    bpy.ops.render.opengl(animation=..., write_still=..., view_context=False)   # ← 只剩这行不可测
finally:
    _after_render(scene, snap)            # 可无头测：还原输出 + 引擎 + report
```

这样 `_before_render` / `_after_render` 都能被测试覆盖，
**不可测面积从「4 份骨架」压缩到「4 行调用」**。4 个 Operator 各自缩到 10 行以内。
