# 架构说明 · 工作台快渲

> `DEVELOPMENT.md` 超过 200 行后按单项目规范拆出本文件。
> 本文件写「怎么搭的」，`DEVELOPMENT.md` 保留「仓库概览 + 问题索引」。

## 它解决的问题

原来要出「工作台引擎那种干净的效果图」，流程是：切到 Workbench 引擎 → 渲染 → 切回 Cycles。
来回切引擎既烦、又容易忘了切回来。

## 核心原理

**关键事实**：`bpy.ops.render.opengl(view_context=False)` 用的是**场景设置**渲染 ——
即「活动相机 + `scene.display.shading`（也就是渲染属性里的工作台面板）」，它**压根不看
`scene.render.engine`**。实测 Cycles 下 `poll()` 依然返回 `True`。

所以「相机视角 + 工作台外观」根本不需要动引擎。内置菜单里那三个入口
（视图 → 视口渲染图像 / 渲染动画 / 关键帧，位于 `bl_ui/space_view3d.py`）同样**没有任何引擎判断**。

## 数据流

```
scene.display.shading   ←── 渲染属性 → 工作台面板（真正决定出图外观）
        │
        │  打开「实时预览」
        ▼
space.shading（所有 3D 视口）  ←── 只用来给人「边改边看」
        │
        │  Panel.draw() 每帧比对差异后推送
        └──────────────────────────────────────► 改参数立刻可见

bpy.ops.render.opengl(view_context=False)
        ▲
        └── 用 scene.display.shading + 活动相机出图，与 render.engine 无关
```

两条独立链路：

- **出图链路**：`scene.display.shading` + 活动相机 → `render.opengl` → 落盘
- **预览链路**：`scene.display.shading` ⇄ `space.shading`（仅视觉，不参与出图）

## 五层结构

依赖方向单向（UI → 预览/快照 → 工具 → 输出），无循环依赖：

```
① 常量与配置           PANEL_CATEGORY / DEFAULT_DIR
                       / _SHADING_ATTRS（挂在 scene.display.shading 上）
                       / _DISPLAY_ATTRS（挂在 scene.display 本体上，如 render_aa）
                       / _PREVIEW
② 输出设置层           _out_dir / _set_image_format / _snapshot / _restore_output
                       / _apply_preview_scale / _apply_frames / _prepare_output
                       / _precheck / _count_png
③ 视口外观同步层       _viewport_spaces / _same_value / _assign_attrs / _copy_attrs
                       / _snapshot_shading / _snapshot_display / _snapshot_viewports
                       / _push_shading / _apply_preview_to_viewports / _restore_viewports
                       / _apply_cavity_preset
                       / _dump_profile / _load_profile / _save_profile
                       / _start_preview / _stop_preview
④ UI 层                WQR_Properties + 8 个 Operator + WQR_PT_panel
⑤ 注册                 _on_file_load（load_post 处理器）/ register / unregister
```

**8 个 Operator**

| `bl_idname` | 作用 |
|---|---|
| `wqr.preview` | 看一眼（不存盘） |
| `wqr.render_still` | 渲染当前帧 |
| `wqr.render_anim` | 渲染动画 |
| `wqr.render_engine` | 引擎式渲染（切 Workbench，`try/finally` 保证切回） |
| `wqr.toggle_preview` | 实时预览开关 |
| `wqr.apply_cavity_preset` | 套用腔体预设（不走快照，永久生效） |
| `wqr.forget_preview_profile` | 忘记记住的预览外观 |
| `wqr.open_folder` | 打开输出目录 |

## 三个必须知道的机制

### 1. 实时预览的「推送」挂在 `Panel.draw()` 末尾

Blender 的内建属性（`scene.display.shading.*`、`space.shading.*`）**没法挂 `update` 回调**。
可行做法是在面板重绘时比对并推送，且**只写有差异的值** —— 否则「写属性 → 触发重绘 → 再写」
会死循环。

### 2. `unregister()` 里若预览还开着会自动还原

否则用户禁用插件后，视口就永远卡在预览状态回不来了。另挂一个
`@bpy.app.handlers.persistent` 的 `load_post` 处理器作废快照（换文件后快照会失真）。

### 3. 预览外观记忆（`preview_profile`）

用户在预览期间调好的外观会**自动**存进 `Scene.wqr.preview_profile`（JSON 字符串，
随 `.blend` 保存）。这样「关掉还原」与「保留我的调整」不再冲突。

**记忆体是两层结构**，因为面板上的外观控件分散在两个不同的 Struct 上：

```json
{
  "shading": { "light": "MATCAP", "color_type": "SINGLE", ... },   // scene.display.shading
  "display": { "render_aa": "16" }                                 // scene.display 本体
}
```

> ⚠️ **「抗锯齿」`render_aa` 不在 `scene.display.shading` 上**，而在 `scene.display` 本体上
> （`View3DShading` 的属性表里查无此物，是 `SceneDisplay` 的属性）。
> 所以它既不进 `_SHADING_ATTRS`、也不参与视口同步 —— 它只影响 `render.opengl` 出图的边缘平滑度。
> 往面板加外观控件前，先确认属性挂在哪一层，见 [问题记录](./问题记录/外观参数-分散在两个Struct上.md)。

**打开预览时的取值优先级**（`_start_preview`）：

```
① 有记忆 且 勾了「记住外观」   → 套用记忆（用户上次调好的样子，shading + display 两层一起写）
② 无记忆 且 勾了「无记忆时套用预设」 → 套用腔体预设 0.3
③ 都没有                      → 用当前场景外观（等于不额外改动）
```

**关预览时的顺序**（`_stop_preview`）：

```
① state["active"] 为真 才 保存记忆   ← 闲置时调用（误触 / 卸载）不能污染记忆
② 还原视口
③ 还原 scene.display.shading 到打开之前
④ 还原 scene.display 本体（抗锯齿）到打开之前
```

> ⚠️ 保存必须在还原**之前**；优先级必须**高于**出厂预设。两条都写进
> [问题记录](./问题记录/预览记忆-保存顺序与优先级.md) 了。

## 还原语义（别混）

| 操作 | 还原什么 | 备注 |
|---|---|---|
| 关掉「实时预览」 | 视口外观 + `scene.display.shading` + `scene.display` 本体（抗锯齿）全部回到打开前 | 包括开预览时自动套用的腔体预设；**但会先把此刻的样子存进记忆** |
| 重新打开「实时预览」 | 不还原，**套用记忆** | 记忆里的外观（两层）覆盖当前场景外观（随后关掉仍能还原） |
| 渲染类按钮（看一眼 / 当前帧 / 动画） | 输出路径、格式、分辨率、帧范围 | **不还原**外观；外观是用户主动调的 |
| 「套用这个预设」 | 什么都不还原 | 就是要把值永久写进场景 |
| 「忘记记住的外观」 | 清空记忆 | 只动记忆，不动当前外观 |

## 输出设置还原

`_snapshot(scene)` 存下引擎、`filepath`、`image_settings`（`media_type` / `file_format`）、
分辨率与百分比、帧范围；`_restore_output(scene, snap)` 写回。

> 5.2 的坑：设置输出格式要注意顺序 —— **先 `media_type`，再 `file_format`**；还原时同样按这个顺序。
